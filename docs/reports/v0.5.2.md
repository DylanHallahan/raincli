## What changed

### Local time everywhere (§17.1, §17.3 A2, A6)
- **The server is unchanged:** it stores and sends UTC ISO-8601, and every displayed timestamp is a `<time datetime>` element.
- **The page formats them:** `static/localtime.js`, one same-origin script under the existing CSP with no inline script, formats each timestamp with `Intl.DateTimeFormat` in the **viewer's own time zone and locale** (12- or 24-hour clock, date order).
  - **On hover:** the full date and time, with weekday, seconds and the time-zone name.
  - **Relative labels** are computed in the browser.
  - **Messages inserted later** are formatted too.
- **Where it applies:** the website, app mode, and the app's bundled local pages. The app uses a **byte-identical bundled copy**, enforced by a test and the bundle check.
- **Without JavaScript:** the existing `YYYY-MM-DD HH:MM UTC` fallback. With JavaScript, no visible timestamp or page chrome contains "UTC".
- **The CLI:** human-readable output is in local time (for example `2026-10-10 10:03:07 EDT`), `--utc` prints ISO UTC, and `--json` stays UTC.

### Archived chats (§17.2, §17.3)
- **Archive a whole conversation.** It leaves the main list for **both** sides, and either side can unarchive it.
- **Nothing is deleted,** and **delivery is never affected.** Archiving is a list state only: inboxes, unread counts, notifications, delivery, acks and events are all unchanged.
- **Position-based state (A1, L1):**
  - An archive records `archived_through_seq`, the newest message the archiver had seen.
  - A conversation counts as archived only while no newer message exists, so a new message from either side always brings it back with its full history.
  - The archive takes `FOR UPDATE` on the conversation, and sends hold `FOR KEY SHARE` from before their sequence number is allocated, so no concurrent ordering can hide an unseen message.
  - Concurrency tests cover one sender and two opposite-direction senders.
- **Authorization:**
  - **Who may:** an endpoint of the conversation (a machine, including through its agent endpoints, or a person), or the person who owns a machine endpoint. Membership is checked within the team on every request.
  - **Everyone else,** including a malformed id, gets the same `404`.
  - **App-mode sessions may archive,** with CSRF.
- **API:**
  - `POST …/conversations/{id}/archive` and `/unarchive`, for machine credentials and the person API (`person:send`);
  - lists take `archived=only|include|exclude`;
  - a machine credential that sends no parameter gets `include`, so older clients never lose a conversation.
- **Website and app mode:**
  - **Archive** is one click with no confirmation, since it can be undone;
  - an **Archived** view lists each conversation with its unread count, who archived it and when, plus **Unarchive**;
  - an archived thread opened directly shows a marker;
  - if a newer message prevented the archive, the page says so.
- **CLI:** `raincli archive`, `raincli unarchive`, `raincli conversations --archived|--all`, and the same under `raincli me`.
- **Migration `0007`:** `archived_at`, `archived_through_seq` and `archived_by_key`, with partial indexes for the list queries. The downgrade drops only those.
- **Guidance:** `SKILL.md` tells agents to archive or unarchive only when their user asks.

## Release notes (draft for main)
- **Times now show in your own time zone and format,** on the website, in the Windows app and in the CLI. Hover for the full date and time. The CLI takes `--utc`.
- **Archive a chat** to tidy your list. It's archived for both sides, either side can bring it back, and a new message brings it back automatically. Nothing is ever deleted, and delivery is unaffected. CLI: `raincli archive`, `raincli unarchive`, `raincli conversations --archived`.
