## What changed

### Server (§18.1)
- **Sign-in throttling** is enforced per attempt, including under concurrency, on every password-checking route. App sign-in has its own rate zone in nginx.
- **Recognised devices:**
  - **Who qualifies:** a device where the user has signed in before may keep signing in during an account-wide slowdown.
  - **How it is bound:** a signed token tied to the user, expiring after 30 days, revoked by a password change, and with its own failure cap.
  - **What it never does:** authenticate on its own.
  - **Where it lives:** the app keeps it in its protected store across sign-out.
- **Conversations** are scoped to exactly one team, structurally and in every read and summary. Migration `0008` brought existing data in line. Nothing was deleted, and archive state was kept.
- **Long-running inbox requests** are limited per credential, per user and per process. Past a limit a request is answered promptly with `Retry-After`; it is never refused.
- **Resource limits:**
  - the machine cap on every way of adding a machine;
  - capped directory history per machine;
  - cleanup of short-lived sign-in codes;
  - attachment storage quotas per user per day and per team over a rolling 30 days (configurable; `rc_admin quota`).
- **Names:** agent names must start with a letter or digit. Person display names may not contain invisible or bracketing characters.
- **Owners:** a machine's owner is shown by display name, and look-alike owners are told apart everywhere: the website, app mode, the CLI and message framing.

### Client (§18.2)
- **A minimum safe version** (0.5.3) is built into the release:
  - versions chosen by the server never go below it;
  - the minimum only ever increases on a machine;
  - a failed update still returns to the version it replaced;
  - only an explicit command-line rollback can go lower.
- **Local app pages:** the server binds its port exclusively and serves only under a per-run secret, which is checked on every call and never logged.
- **Links leaving the app:**
  - only web (`https:`) and mail (`mailto:`) links leave, after validation and re-serialization;
  - mail links keep only safe fields;
  - new windows follow the same rule.
- **Validation:** identifiers and names from the server are checked over their whole value, and a message id must equal the one requested. Only fixed reason codes are reported to the server; error details stay local.
- **Quieter polling:** the client honours `Retry-After` on an empty inbox answer.
- **A faster post-sign-in hint:** the "connect your agents" probe is bounded to a few seconds.
- **Docs:** SETUP recommends `list` trust for sensitive machines, and says to keep automatic updates on.

### Tests and tooling
- **Every item has regression tests.** The server tests run against real PostgreSQL. The app items are covered by the Windows app e2e (exclusive bind and path secret, and new windows).
- **No test runs a real agent:** the Codex and Claude Code probes are stubbed, with a guard test. Pytest keeps only failed tests' temporary directories.
- **The Windows e2e** derives its test installer versions from the source, so they never fall below the minimum safe version.

## Release notes (draft)
- **Stronger sign-in protection:**
  - devices you've used before keep working during a sign-in slowdown on your account;
  - sign-in limits are applied more strictly.
- **Owners shown:** machine owners are shown next to machine names in the CLI and in delivered messages, and look-alike names are told apart.
- **Downgrade protection:** the client won't install an older release than the minimum safe version, and only an explicit command-line rollback can go below it; a failed update still returns to the version it replaced.
- **Storage limits:** attachment storage limits per person and per team (both adjustable by the operator).
- **The Windows app:** local pages and outgoing links are locked down further.
- **Recommendation:** keep automatic updates on. For sensitive machines, consider `raincli trust --mode list`.
