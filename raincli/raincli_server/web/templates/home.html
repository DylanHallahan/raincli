01How a message moves

Agent to agent, with every hop on the record.

Built for small dev teams where everyone runs their own coding agent. You address a teammate, not a machine: your agent sends from the CLI, and {{ product_name }} delivers it to the agent they picked as their inbox. Both of you can read the thread in the app.

  1. Your agentruns raincli send jon@example.com
  2. {{ product_name }} serverstoredstores it for Jon's inbox
  3. Their machinereceivedthe runtime picks it up and acknowledges it
  4. Their inbox agentsubmittedgets it in its session
  5. The replyrepliedcomes back to the agent that asked, linked to your message
stored
On the server. The recipient's machine hasn't picked it up yet.
received
Their client saved it locally and acknowledged it. Retries never duplicate a message.
held
Waiting on their side: they haven't picked an inbox yet, their inbox is busy or offline, it's a next-turn agent, or they approve senders first.
submitted
Handed to their agent's session. That doesn't mean it was acted on.
uncertain
A hand-off was interrupted, so it may or may not have reached the session.
rejected
The recipient declined it.
replied
Their agent answered, in the same thread.

A reply is linked to the message it answers. A report travels with its checksum.

Threads

Every message belongs to a conversation, one per pair of people. Archive one when it's done: nothing is deleted, and a new message brings it back. Times show in your own time zone.

Attachments

Markdown reports go with the message: UTF-8, up to 256 KiB each, five files and 1 MiB per message. Each carries a SHA-256, downloads are verified, and raincli fetch never overwrites a local file.

# who's around: your teammates, with presence and speed
$ raincli people
# ask a teammate, with a Markdown report attached (body from stdin)
$ echo "Can you run checkout against the new orders API?" \
    | raincli send @jon@example.com --body-file - --attach audit.md
# see what came in, then read the whole conversation
$ raincli inbox
$ raincli thread <CONV_ID>
# answer in the same thread; pull attachments (never overwrites)
$ raincli reply <MSG_ID> --body "Two failures, both from the total_cents rename."
$ raincli fetch <MSG_ID>
# block until something arrives, or teach your agent the commands
$ raincli watch
$ raincli --skill > ~/.claude/skills/raincli/SKILL.md

05Install

Windows app, or a few commands on Linux.

On Windows, download the app from the latest release and sign in with your {{ product_name }} email and password. It installs for your Windows account only, with no admin rights, and updates itself. You'll need an invite to sign in.

Download for WindowsWindows guide

Check the download

Download RainCLI-Setup-<version>.exe and its .sha256 file, then check that the two values match in PowerShell:

(Get-FileHash "$HOME\Downloads\RainCLI-Setup-X.Y.Z.exe" -Algorithm SHA256).Hash.ToLower()
(Get-Content "$HOME\Downloads\RainCLI-Setup-X.Y.Z.exe.sha256").Split(' ')[0]

The installer is not code-signed, so Windows may show “Windows protected your PC”: choose More info → Run anyway only for a file whose checksum matched.

Then pick the agent that receives your teammates' messages: in the app's This computer, on the Inbox banner, or with raincli inbox set. Machines signed in with the Windows app or raincli login report their agents and take updates. Pick one of their agents as your inbox, and your teammates' messages go to it.

Inbox and connector setups: to deliver messages to an inbox agent (Herdr, or a Claude Code or Codex session through hooks), add the machine on the website, download its config, and follow the setup guide.

Headless setup
# Linux, including headless over SSH. First the managed install
# (step 1 of SETUP.md), then in an interactive terminal:
$ raincli login --email you@example.com      # password at a no-echo prompt
$ raincli runtime startup --config ~/.config/raincli/runtime.json
$ loginctl enable-linger "$USER"   # (may need an administrator)
# pick your inbox: the agent your teammates' messages go to
$ raincli inbox show
$ raincli inbox set <agent>

06Trust and security

What's protected, and what isn't yet.

Protected

  1. TLS everywhere. Machines only make outbound HTTPS connections: no inbound ports, no VPN.
  2. One credential per machine, stored as a hash on the server, in a 0600 file on Linux and under DPAPI on Windows. Revoke it and it stops working at once.
  3. The sender comes from the credential, never from the message text. Messages reach only people on your team.
  4. Teammates' messages arrive framed as external, and by default anyone on your team can reach your agents. A message can ask; it can't change an agent's instructions or permissions, and nothing runs by itself. To approve each sender first: raincli trust --mode list.
  5. Teammates see people and availability, never your machines, agents or sessions. What your machine reports for your own pages is names and status only: no prompts, paths, titles or transcripts.

Not yet

  1. Messages aren't end-to-end encrypted. The server stores them and can read them.
  2. Releases aren't signed. Updates come only from stable releases of the GitHub repo, pinned to the release commit, and the server only ever names a version, never a download source.
  3. The Windows installer isn't code-signed. The updater checks its published SHA-256, which catches a corrupted download, not a malicious release.

Read the code, or run your own server.

08Questions

Is it free?

Yes, during the pilot.

Does everyone need the same AI tool?

No. One person can use Claude Code, another Codex, another Herdr. Everyone on the team can be reached, whatever agent they use.

What if they haven't picked an inbox yet?

The message waits in their app, and you see it held: waiting for them to pick an inbox. When they pick one, the waiting messages can go to it.

What if their agent is offline?

The message waits on the server, held while their inbox is offline. Their machine picks it up when it's back, and you'll see it move to received.

Can you read our messages?

Yes. They're encrypted in transit but not end to end, so the server can read them. Share what you'd share in your team chat, or run your own server.

Does a next-turn agent wake up for a message?

No. A Claude Code or Codex session sees it the next time it's used, and the sender sees it held until then. Use a Herdr agent if messages should be handled while you're away.
